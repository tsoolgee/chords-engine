# מסמך אב — תוכנת מילים ואקורדים לשירים בעברית

זהו המסמך המאוחד של המוצר. הוא מבוסס על האפיון המקורי, מותאם למנוע שכבר נבנה
(`chords_engine`), ומסודר לפי סדר עבודה.

- הפירוט של כל מסך נמצא ב-[UI_SPEC.md](UI_SPEC.md)
- החוזה הטכני מול המנוע נמצא ב-[API.md](API.md)

**עדכון:** גרסה 0.2 כוללת תוכנה מלאה (`release/Chords.exe`) עם ממשק אב-טיפוס שמממש את רוב ה-MVP.

**מקרא סטטוס** (בכל שורה בטבלאות):

| סימון | משמעות |
|---|---|
| ✅ | קיים במנוע ונבדק |
| 🔧 | צריך להוסיף למנוע (מוערך כקל/בינוני/כבד) |
| 🎨 | באחריות הממשק בלבד |

## 1. חזון

תוכנת Windows בעברית (RTL) שמשלבת ספריית מוזיקה, נגן, זיהוי מילים ואקורדים,
עורך, כלי תרגול ומצב הופעה.

תהליך העבודה הבסיסי צריך להיות פשוט:
**גוררים שיר ← לוחצים "נתח" ← ממשיכים לעבוד ← המילים והאקורדים מופיעים ← מנגנים יחד עם השיר.**

שלושה עקרונות מנחים את כל ההחלטות:
- **מהירות מורגשת:** תוצאות מופיעות בהדרגה והממשק לא נתקע אף פעם.
- **דיוק שניתן לתקן:** כל זיהוי אפשר לערוך, ותיקונים לא הולכים לאיבוד.
- **נוחות בזמן נגינה:** המשתמש תמיד רואה איפה הוא בשיר, מה האקורד הנוכחי ומה הבא.

## 2. ארכיטקטורה (הוחלט)

```
┌──────────────────────── ממשק (UI) ────────────────────────┐
│  HTML/CSS/JS בתוך WebView2 (Edge)                           │
│  נגן שמע/וידאו · תצוגה · עריכה · Undo · מצב הופעה · הדפסה   │
└───────────────▲──────────────────────────────┬─────────────┘
                │ HTTP + SSE  127.0.0.1:8765    │
┌───────────────┴──────────────── מנוע (Python) ▼────────────┐
│ MediaEngine    ffmpeg/ffprobe: פענוח, Metadata, Cover, Waveform│
│ AnalysisEngine whisper.cpp (עברית) · lv-chordia · librosa    │
│ SyncEngine     שיבוץ אקורד→אות, שורות, בתים                   │
│ Library        תיקיות/אמנים/אלבומים (SQLite)                 │
│ ProjectManager AI-result / עריכות / נעילות · Cache · Export  │
│ JobQueue       ניתוח ברקע, תור, ביטול, תוצאות חלקיות          │
└────────────────────────────────────────────────────────────┘
```

**למה הממשק ב-WebView2:**
- הגרפיקאי עובד ב-HTML/CSS רגיל, ותמיכה ב-RTL מגיעה מובנית.
- נגן השמע והווידאו כבר מובנה בדפדפן (`<audio>`/`<video>`), כולל שינוי מהירות בלי שינוי גובה (`preservesPitch`) ודילוג מהיר.
- הדפסה ל-PDF מובנית.

המעטפת יכולה להיות **pywebview**, כך שהכול נשאר ב-Python ונארז ל-EXE אחד,
או מעטפת C# קטנה. המנוע לא משתנה בשום מקרה.

**MediaEngine מחולק בין הצדדים:**
- **המנוע אחראי על:** קריאת Metadata, חילוץ Cover, המרה ל-PCM לניתוח ו-Waveform.
- **הממשק אחראי על:** ניגון, דילוג, מהירות ועוצמה.

כך אין צורך לנגן דרך Python.

## 6. ניתוח

### 6.1 מה מזוהה
| | סטטוס | הערה |
|---|---|---|
| מילים עם זמן לכל מילה | ✅ | whisper.cpp + ivrit-ai |
| אקורדים: התחלה, סוף, סוג (~170 סוגים, כולל בס) | ✅ | lv-chordia |
| רמת ביטחון לכל אקורד | 🔧 קל | ממוצע הסתברות המודל על פני הקטע. יש כבר `p` לכל מילה ✅ |
| BPM | ✅ | ניתן לתיקון ידני ✅ |
| סולם | ✅ | ניתן לתיקון ידני ✅ |
| מבנה: פתיחה / בית / פזמון / מעבר / סיום | ✅ בסיסי | פזמון מזוהה לפי חזרת טקסט. 🔧 בינוני: שיפור לפי חזרת רצף אקורדים |
| סנכרון מילים↔אקורדים↔זמן | ✅ | |

### 6.2 רמות ניתוח
| רמה | מה רץ | זמן משוער לשיר של 4 דק' במחשב i3 |
|---|---|---|
| ⚡ מהיר | אקורדים + BPM + סולם, בלי מילים | כדקה |
| ⚖️ רגיל (ברירת מחדל) | + מילים (מודל q5, greedy) | 6–9 דק' |
| 🎯 מדויק | + תזמון DTW, מודל מלא, הפרדת שירה (demucs) | 15–25 דק' |

כל הרמות כבר קיימות כאפשרויות במנוע ✅. צריך רק לארוז אותן כשלוש בחירות בממשק 🎨.

### 6.3 ניתוח חי (תוצאות מופיעות תוך כדי) — ✅

המציאות במנוע: זיהוי האקורדים מהיר (כדקה לשיר), והתמלול איטי (דקות).
לכן סדר ההופעה יהיה כזה:

1. **תוך שניות:** Metadata, Cover, Waveform. הנגן מוכן לנגן.
2. **תוך כדקה:** ציר האקורדים המלא, BPM וסולם. אפשר כבר לנגן עם אקורד נוכחי ואקורד הבא.
3. **כל כמה שניות:** מתווספות שורות מילים, לפי הסדר. whisper מדפיס כל קטע ברגע שהוא מוכן, והמנוע ישבץ עליו אקורדים וישלח אותו.
4. **בסיום:** ניקוי אחרון וחלוקה לבתים.

אירועי SSE שיישלחו (בהמשך לאירוע ההתקדמות הקיים):

```
progress{stage, progress}
media_ready{meta, cover, waveform}
chords_ready{timeline, key, tempo, beats}
lines_added{lines[], transcribed_until}
completed{song_id}
```

בממשק, פס ההתקדמות מציג קטעי זמן: ✓ 0:00–0:30, ● 0:30–1:00, ○ ...

## 13. גרסה ראשונה (MVP) — סדר עבודה

דברים שכבר קיימים במנוע (קאפו, תרשימים, מבנה בסיסי) עברו ל-MVP, כי הם לא עולים עבודה נוספת.

**מנוע (לפי הסדר):**
1. בדיקה על 5 שירים עבריים אמיתיים וכיול (חובה לפני כל דבר אחר)
2. ניתוח חי ב-SSE (6.3)
3. ספרייה ב-SQLite: תיקיות, אמנים, אלבומים, Metadata מלא, Cover, ייבוא תיקייה, חיפוש
4. Waveform, רמת ביטחון לאקורדים, תיקון זמן, שמות אקורדים מלאים
5. אריזה ל-EXE (PyInstaller + pywebview)

**ממשק:**
- ספרייה + Drag & Drop
- נגן + תור
- מסך שיר: תצוגה, סנכרון, עריכה, Undo, שמירה אוטומטית
- טרנספוזיציה, קאפו, מהירות, Loop
- מצב נגינה
- ייצוא TXT, PDF, העתקה

**אחרי ה-MVP:**
- מצב הופעה + setlist
- נעילת תיקונים
- ניתוח מחדש של קטע
- Recovery
- DOCX/CSV
- שיפור זיהוי המבנה
- שינוי גובה צליל לפי הטרנספוזיציה

## 14. מגבלות שצריך לדעת מראש

- **מהירות התמלול:** במחשב בלי כרטיס מסך, תמלול מלא לוקח בערך פי 2 מאורך השיר.
  לכן ניתוח חי (6.3) ועבודה בזמן הניתוח הם הכרח, לא מותרות.
- **הזיהוי לא יהיה מושלם.** שירה עם מוזיקה קשה לתמלול יותר מדיבור.
  האפשרות להדביק מילים נכונות (היישור לוקח שניות) והעורך הם חלק מהליבה.
- **טרנספוזיציה משנה רק את האקורדים**, לא את השמע, עד שיתווסף pitch-shift.
  צריך לכתוב את זה ליד הכפתור.
